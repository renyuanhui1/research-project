# 机场多目标模板条件化视觉抵近：总体执行方案

本文是总体规划，各阶段的具体命令和代码细节由执行方读代码后确定，并在动手前和用户确认。项目背景见[README](../README.md)，结构见[架构说明](../docs/ARCHITECTURE.md)，已有结果见[实验记录](EXPERIMENTS.md)。

## 一、目标与边界

**当前验收目标**：在现有Airport场景中，目标与指定观测部位从起始画面即可见。提供带部位ROI的模板，由原视觉控制器完成抵近、距离停车、连续悬停与拍照，并用独立终点图像和状态核验指定部位及停车稳定性。先执行已有飞机任务，记录每次准备与飞行的实际结果。

**最终目标**：给定一张目标的俯视模板，无人机从斜上方抵近目标，到小距离后悬停拍照；如果目标是仓库，从屋顶破洞进入内部。一个模型要能处理多类目标，包括没训练过的实例。

**目标类别**：受损飞机（一侧机翼、驾驶舱、尾翼）、大面积损伤的仓库、柱体受损的塔台，以后还会增加。

**已定设定**

- 模板来源：高空垂直俯视图，从中截取目标。以后由上层评估体系下发"二次抵近任务"，上层目前没有接入。
- 勘测：沿用现有抵近控制，到达停车距离后拍下目标图像，不做绕飞规划。
- 入室：只走屋顶破洞，沿用现有的屋顶洞口入室链路。
- 资产：由用户自己导入UE。资产是整体网格，没有按部件或损伤区拆分材质。

**不在本期范围**：侧墙破口进入、动态避障、绕飞覆盖规划、真实照片模板、实机部署。

**已知结论，执行时必须考虑**

- 冻结DINO的跨视角匹配不可靠：正前上方起点使用侧前方参考时，垂尾落点错误；斜视入室时，俯视模板在下降约17.7米后分数降到0.393而失锁。
- 学习匹配器的定位精度不是瓶颈，置信度才是：95%精度下垂尾召回只有0—0.4%；机头、主翼的100%来自基率，不能作接受判据。
- 3像素容差对大掩码不等价（主翼中位距离−18.8像素仍判正确），跨部位、跨目标比较需要面积归一化指标，目前尚未实现。
- 采集时UE窗口不能最小化（最小化后约2.8 FPS）；场景加载后要等约30帧曝光收敛，采集器和准备入口已有等待判据。
- 场景里现成的同类实例：小机库约27组、大机库约10组、仓库约19个、塔台2座、飞机2架。同一网格复制出的实例外观几乎相同，只有位置、朝向和背景不同。
- 一个建筑目标通常由多个actor组成（主体、门、内部钢梁等）。

## 三、技术路线

**模型思路**：模板条件化匹配器。模板和搜索图共用冻结的DINOv2编码器，模板特征与搜索图特征做相关或交叉注意力，解码出定位热图，另外单独训练一个置信度输出。分两级：

1. **全图粗定位**：替代现在只认飞机的"整机原型"，在整幅斜视图里找到模板对应的目标，给出裁剪框。
2. **局部精定位**：在裁剪块内输出抵近点，用于控制和深度取样。

**标签**：默认用整目标标签，即射线命中目标网格的像素。需要部位级抵近时，在目标坐标系里画区域盒，方式与现在的机头/主翼/垂尾定义相同。

**坐标的使用口径**（与现有项目一致）：目标坐标只用于准备模板、布置起点、生成标签和事后评价，不能进入在线感知和控制。

### 阶段0：基线与跨视角诊断（离线，不连仿真）

**目的**：在投入采集前，量化现有方法在"俯视模板→斜视画面"条件下差多少。

**内容**

1. **跨机型迁移**：先用F-14三分支权重在F-14各自的留出折上复现已记录的机头74.3%、主翼98.7%、垂尾86.5%，确认权重正确；再用F-14的5个折模型分别推理F-35全部帧，报均值±标准差，与F-35自训结果（79.2%/95.4%/95.7%，按垂尾/主翼/机头）对比。F-35只能比定位，没有接受层特征。
2. **俯视模板基线**：从两张80米俯视图中按网格投影截出整机模板，用冻结DINO在两架飞机各5000帧斜视图上匹配，统计峰值落在整机掩码内的比例，按12—30/30—60/60—100/100—150米分档。对照组为当前使用的斜视模板。
3. **面积归一化指标**：实现并与3像素指标并列报告。

**产出**：三组对照表，写进实验记录。

**验收**：权重复现误差≤0.5个百分点；俯视模板与斜视模板的差距按距离给出。

### 阶段1：目标库与俯视模板普查（需要仿真）

**目的**：建立"目标→俯视模板"的目标库，作为训练、评价和以后上层下发任务的统一入口。

**内容**

1. **定义目标**：按空间位置把多个actor聚类成一个目标。每个目标记录编号、类别、组成actor、参考点、是否有屋顶开口、是否受损。
2. **导出几何**：把目标库中所有actor的网格导出为现有npz格式，用于掩码和评价。
3. **俯视采集**：对每个目标在固定高度垂直俯视拍照，高度按目标尺寸选择，保证目标完整入画并留有余量；记录高度、地面分辨率和相机位姿。
4. **截取模板**：按网格投影框裁剪，同时保存模板元数据。
5. 用户导入损伤资产后，同样走这一阶段并入目标库。

**产出**：目标库配置、模板图与元数据、普查报告。

**验收**：每张模板完整包含目标、曝光正常；在总览图上按类别人工抽查。

### 阶段2：多目标斜视训练数据采集（需要仿真）

**目的**：为每个目标采集带标签的斜视帧。

**内容**

1. **泛化采集器**：现在的采样以飞机前向轴为基准，改为以目标坐标系为基准，并按类别设定采样几何：
   - 飞机：机头前方扇区，同时覆盖侧向。
   - 机库/仓库：全方位360°。
   - 塔台：全方位360°，按高度分层。
   - 相机俯角保持−35°，与部署一致；距离沿用12—150米分层。
2. **整目标掩码与遮挡处理**：现有渲染器只对目标网格做射线投射，不知道前方有无其他物体。机库群中遮挡常见，需用实测深度与射线距离做一致性检查，剔除被遮挡像素。
3. **数据量**：学习曲线显示1000—2000帧时定位精度接近饱和，按每目标1000—2000帧规划。5000帧约占18 GB，本地剩余空间约860 GB，按目标数估算总量。

**产出**：每个目标一个采集目录，报告字段与现有格式兼容。

**验收**：抽查近、中、远三档掩码与图像对齐；遮挡剔除结果人工确认。

### 阶段3：模板条件化模型（离线训练，服务器237）

**目的**：训练"给模板就能定位"的模型，并在没见过的目标上评价。

**内容**

1. **模型**：按第三节的两级结构实现。训练时对模板做随机尺度、旋转和亮度增强，因为俯视模板的朝向任意。
2. **数据划分**，三层，任何一层都不能按帧随机划分：
   - **留出实例**：每类留出若干实例。只能说明换位置、背景、视角后仍能定位，因为同网格复制品外观相同。
   - **留出外观**：留出不同网格的实例，主要依靠导入的损伤资产。
   - **留出类别**：整类不参与训练（例如塔台），测零样本。
3. **对照组**：冻结DINO模板匹配；固定通道的`HeatmapNet`（只适用于见过的目标）。
4. **置信度**：单独训练置信度输出，阈值在留出目标上校准，不在训练用的同一批OOF上选。
5. **产物保存**：每次训练保存权重、种子、配置哈希、数据划分清单和git commit，写一份清单文件。

**产出**：模型权重、评价报告、各层对照表。

**验收与决策点**

- 留出实例上命中率需明显高于冻结DINO，95%精度下的覆盖率需有实际意义；具体阈值在阶段0完成后与用户商定。
- 留出实例达标、留出类别不达标：结论写为"类内泛化"，再决定是否增加类别多样性。
- 留出实例也不达标：停下与用户讨论替代方案（补低空斜视模板、多视角模板、加入RGB-D几何约束等），不继续扩充数据。

### 阶段4：独立视角与连续序列验证（需要仿真）

**目的**：瞬移采样与真实飞行分布不同，需要用新起点和新方向的数据验证冷启动截获。

**内容**：选少量留出目标，参照2026-11-13"垂尾重新截获的独立视角验证"的协议，采集新起点、新方向数据，以及一段真实连续飞行序列；采集前冻结方法与阈值。

**验收**：冷启动截获率、误接受率和延迟；单帧推理耗时在控制周期可承受范围内。

### 阶段5：在线接入

1. **影子模式**：在`run_approach.py`中将新模型作为旁路观察者，只记录预测、置信度和耗时，不参与控制；跑若干次真实抵近。
2. **接管控制**：影子模式达标后，由新模型提供控制中心，保留现有深度停车与全部保护。
3. **勘测输出**：到达确认后悬停，保存目标图像、相机位姿和深度。
4. **仓库入室**：抵近到仓库上方后交接给现有屋顶洞口入室链路，洞口模板同样从俯视图截取。

**验收**：每类目标至少完成一次在线抵近并拍照，至少完成一次仓库入室；按现有口径记录，预检失败不计为成功。

### 阶段6：总评

汇总三层划分下的离线结果和在线结果，写清结论的适用范围：同一场景、固定−35°相机、仿真模板。
