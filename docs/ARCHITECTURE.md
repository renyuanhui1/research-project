# 项目结构与运行原理

## 模块

| 路径 | 职责 |
|---|---|
| `src/common/` | 项目路径、场景档案、日志归档、图像解码与分割ID映射 |
| `src/capture/` | 模板与起点准备、传感器采集、HDF5整理 |
| `src/perception/` | 冻结DINO、模板原型、图像全局匹配与深度点云 |
| `src/control/` | 单机抵近控制 |
| `src/debug/` | 传感器、目标对象、匹配与地图诊断 |
| `src/debug/maps/` | UE几何导出、碰撞采样、网格转换及占用栅格生成 |
| `src/evaluation/` | 位姿、包围盒及部位投影的离线评价 |
| `src/visualization/` | ROS2地图发布、匹配图与轨迹回放 |
| `src/px4/` | MAVSDK/PX4接口与航向检查 |

Python入口定位项目根目录，并只将`src/`加入搜索路径；跨模块使用`common`、`perception`、`control`等包导入。资产路径相对项目根目录解析，不依赖启动工作目录。`common/profiles.py`加载`--profile`或`UAV_SCENE_PROFILE`指定的JSON；默认使用`airport`。

## 跨机器仿真连接

WSL与服务器237均连接Windows主机178上的UE。两端`configs/scenes/airport.json`的`simulator.address`统一填写`192.168.31.178`；入口直接读取该字段，`--profile`和`UAV_SCENE_PROFILE`用于选择档案。运行时选择一端使用完整客户端，结束并断开后再切换另一端。

ProjectAirSim通过TCP 8989传输相机等话题，通过TCP 8990处理服务请求。UE需在机场关卡进入Play；Windows入站规则允许来源`192.168.31.237`访问这两个端口。图像接收质量以实际独立帧率及日志为准。PX4还使用TCP 4560和UDP 14540/14588，飞控部署地址与链路需单独核验。

## 配置与数据流

```text
configs/scenes/<scene>.json
  ├─ configs/simulation/*.jsonc → ProjectAirSim无人机与传感器
  ├─ configs/missions/*.json → 起点、速度、相机俯角及停车阈值
  ├─ data/templates/ → 模板与特征统计图像
  └─ data/maps/ → 背景栅格、飞机三角面和精细表面体素

src/capture/prepare_scene.py
  → 已知坐标采集模板、几何投影ROI、起点布置
  → runs/approach/<id>/runtime-scene.json + scene-profile.json
  → template.json + validation-frames.npz + controller-setup.json

src/control/run_approach.py
  → 远近景匹配预检
  → RGB → 冻结DINO → 标准化 → 模板相似度/softmax中心
  → 中心滤波 + 深度 → 机体系速度 → ProjectAirSim
  → runs/approach/<id>/原始记录、双路录像、日志和viz_dump

src/visualization/matching.launch.py
  → 地图节点：OccupancyGrid + MarkerArray
  → 回放节点：viz_dump → 位姿、轨迹、匹配画面 → RViz
```

参考点坐标用于采集准备与离线评价，正式抵近的速度不由目标坐标生成。无人机位姿还用于高度保护、轨迹显示与评价。地图提供空间对照，不参与当前速度控制或障碍规避。准备过程需核对UE目标变换与保存地图一致。

地图显示由二维地面色块、背景碰撞体素和按高度着色的飞机表面体素组成。地图发布时先发送空命名空间的`DELETEALL`清除已有标记，再发送当前地图几何。

## 感知、控制与记录

`Fingerprint`用统计帧计算特征均值、方差，构造整图及ROI原型；不训练编码器。远段使用整机原型，可信深度连续进入45米后切换部位ROI。图像softmax中心经指数滤波后输入控制。

主入口支持斜俯视和俯视。斜俯视100米任务远段水平速度上限3米/秒，近距12米内合速度限制0.35米/秒。停车要求3张独立深度帧满足阈值；保留高度、深度、碰撞、失锁和图像超时保护。部位匹配须通过对应准备目录的预检，各目标结果见[实验索引](../reports/EXPERIMENTS.md)。

前摄与跟随RGB为1920×1080，深度为640×360，采集请求间隔0.0167秒。跟随相机位于机后3米、上方1.5米。深度按`16FC1`米制解码，episode存储保留fp16；无效值记0。不同分辨率测距使用归一化图像坐标。录像按30FPS编码，实际独立源帧率由报告与帧索引给出，含重复帧时不能视为真实30FPS采集。

## 文件与坐标约定

`src/visualization/opening_replay.py`读取已保存记录，生成`rviz/manifest.json`和`rgbd-map.npz`，发布`/opening/map`、`/opening/markers`、`/opening/path`和`/opening/view`。点云由开发采集的透视深度与保存的相机位姿投影到ENU，按0.35米去重，不运行SLAM。`matching`模式逐项显示离线结果及9个采集位姿，不发布轨迹连线；`entry`模式发布实际坐标飞行的417条位姿轨迹，照片只在已有4个采集位置更新，并显示持有照片的时间差。回放按索引计时，保留原始时间戳，不补造连续照片；不连接仿真。

洞口开发使用`src/capture/collect_opening_views.py`按已知目标坐标采集独立开发序列，保存原始RGB、深度、位姿和运行配置；它只采集屋顶上方视图，不执行视觉抵近。入口检测到已有Drone1时默认拒绝重载；显式传`--reset-scene`会先记录已有无人机状态，再重载仿真准备起点。

`opening_replay.py --mode alignment --flight-dir <控制目录>`读取实时对准的`signals.jsonl`、RGB-D及保存的匹配图，发布每条实际控制观测的位姿轨迹和对应画面。背景点云每10组RGB-D选一组并包含末帧，使用保存的深度相机位姿投影；全部观测仍参与回放。默认按控制记录的`time_s`间隔播放，`--speed`缩放时间，循环末暂停2秒；显式传`--rate`则按索引播放。青色标记为近层平面上的投影空隙参考，蓝色标记为保存的无人机位置；不计算新匹配、不运行SLAM、不连接UE。

`render_opening_features.py`读取控制记录中的候选裁剪、固定模板、参考统计和原始RGB-D，离线重建32×32空间DINO相似度及RGB-D跟踪点。红色按`√(softmax/max_softmax)`叠色，仅用于显示；原候选平均分数仍单独核对，不把显示权重作为控制权重。绿色大十字在DINO阶段使用记录的洞口点，在RGB-D阶段将记录的水平误差投影到当前地面深度平面；密集绿色小点为RGB-D角点与LK跟踪所用的特征，包含关键帧刷新后新提取的点。重算结果核对原分数、位姿及源记录哈希，通过后由`opening_replay.py --feature-view-dir`同步播放。`--image-window`另开大图窗口，图中明确标识离线重算及当前控制来源。

`src/evaluation/eval_opening_matching.py`读取`configs/missions/hangar_opening_validation.json`，从固定参考图裁剪洞口模板，仅用参考图计算`Fingerprint`标准化统计量；验证帧不参与统计。它比较整帧DINO中心与由该中心决定的原始高清候选裁剪，输出原图像素坐标、响应和诊断图。人工洞口轮廓只用于参考图自检，响应中心不作为可通行位置；输出不构成穿越验证或飞行放行依据。

启用`--depth-geometry`时，`perception/opening_geometry.py`先把透视射线深度转换为相机前向深度，按深度分层提取封闭候选，排除与画外相连的远层。形态学归组只生成身份匹配候选，实际可见空隙保留横梁及无效深度。各候选原始RGB裁剪由固定模板的DINO空间patch对应排序；开发分数阈值以下不输出建议落点。落点的投影半径只描述当前视线下的二维空隙，不包含遮挡后的三维通道净空。该方法假设已知内参的垂直俯视深度，当前开发数据使用90°水平视场。

`perception/opening_matching.py`提供离线评价与实时控制共用的候选空间DINO排序。`control/run_opening_alignment.py`只连接已有的空中Drone1，读取实时RGB-D和相机内参，要求90°水平视场、垂直俯视、同视点及无畸变。RGB和深度均须为独立递增时间戳，配对偏差上限0.15秒、输入帧龄上限0.75秒；推理及保存之后再次核对帧龄。三帧候选连续获取后，将图像偏差乘近层代表深度换算为相机平面位移，再按该帧相机旋转转换成NED水平速度；速度计算不使用目标世界坐标或相机世界位置。

水平对准使用最高0.35米/秒、0.3秒脉冲，每次执行后发送悬停指令，再获取动作后的独立帧。定高指令保持入口读取的初始NED Z；绝对高度45—105米、相对高度漂移1.5米及起点水平半径15米作为独立保护。弱匹配、候选歧义、候选框或空隙点突变、屋面距离不足、图像过期及新碰撞事件停止试验。对准确认要求5张独立帧、至少2秒满足0.5米近似图像平面误差和0.15米/秒水平速度；这些是实验参数，不是已校准定位精度。入口保存原始RGB-D、匹配图、相机元数据、`signals.jsonl`与`report.json`，包含失败输入和最终悬停状态；不执行下降或通道穿越。

`collect_opening_views.py --alignment-start-only`用于当前无Drone1时按已知坐标准备65米高起点，只采集一组RGB-D后悬停。准备飞行与视觉闭环分开归档；控制入口不重载场景、不起飞、不解锁。

准备入口的`--camera-down-angle`指定镜头朝水平线下方的角度；斜视起点默认在目标包围盒中心的南侧，水平偏移为“65米与屋顶最高点高度之差÷角度正切”。`--start-offset-ne N E`可明确指定实验起点偏移。坐标与包围盒仅用于准备，正式控制不读取这些目标坐标。

`run_opening_alignment.py --enter`在对准确认后初始化RGB-D视觉参考系，继续下降抵近并穿过洞口。`perception/rgbd_entry.py`在洞内可见远层上提取特征，以LK连续跟踪，使用当前深度及鲁棒三维刚体配准估计相机相对参考系的位置。移动超过4米、三维残差增大或内点变少时刷新局部视觉关键帧，新特征用当前视觉变换转回同一参考系；不使用UE位置修正。残差同时在像素和米制空间检查，近景像素限值随当前深度换算。速度由该视觉相对位置及相机朝向生成，不使用UE目标位置或相机世界位置；UE高度与视觉下降量的差异仅作独立停止保护。距估计屋面25米以外仍校验DINO对应，近处由已验证的RGB-D锚点交接。

入室通道使用水平半宽1.25米的采样棱柱，从初始相机下方3.5米至估计屋面下方8米及包络余量，按0.25米采样；深度按5×5邻域最小值处理，保留横梁及无效像素。采样点前方须有超过0.3米加半个采样体对角线的测量余量。近盲区由小步动作及中心深度保护约束；已验证但随后出视野的包络点最多缓存45秒，因此此控制假设场景静止，不构成动态障碍保证。观察到障碍、无效深度、未知/过期通道或视觉失锁立即停止。

入室阶段每次脉冲0.8秒后悬停复测；远段下降速度上限0.8米/秒，距估计屋面10米内及穿越阶段上限0.35米/秒，水平上限0.25米/秒。水平偏差超过0.35米时先修正再下降。下降到估计屋面下方8米附近后，以连续独立观测和低水平/垂直速度确认内部悬停，将FrontCamera临时转为前向采图并恢复俯视，不重载场景；检查图像近白比例与标准差，拒绝严重过曝或无变化图像。`entered`与`aligned`分别记录，停止在对准阶段不计入室。绝对高度下限8米、中心深度下限5米及视觉/UE下降量差异1.5米作为独立保护。

`run_opening_alignment.py --enter --oblique`使用斜俯视相机，要求光轴朝水平线下方40—80度，保持90度水平视场及RGB-D配准。深度先反投影为三维点，再按相机姿态提供的重力方向分层，假设候选屋面近似水平。洞口像素射线与估计屋面求交得到视觉参考系中的穿越点；洞内地面深度不作为屋面交点距离。固定俯视模板继续承担DINO候选排序，弱匹配仍停止，斜视外观可靠性需由对应图像验证。

斜向通道中心线从视觉交接时的相机位置经过洞口交点，并延伸到估计屋面下方8米；终点不使用内部世界坐标。通道以向下进度参数化，水平速度为路径斜率乘下降速度加横向纠偏。两者协调限速，水平偏差超过0.35米时停止下降；起点水平半径保护为60米。机体水平包络根据斜率扩大，以包含机体上下表面扫过的范围；深度余量为0.3米加斜向采样单元最大对角线的一半。近盲区、0.25米采样与45秒静态缓存约束同样适用，视野不能覆盖完整待检包络时停止。光轴附近5米测距保护在斜视下表示前下方障碍距离，不等同于正下方离地高度。

斜向DINO交接还依据当前候选上下文裁剪框到图像边界的归一化距离：最小边界余量降至8%或更少时，在该帧DINO身份和视觉几何一致性仍通过、RGB-D位姿和通道均有效的条件下，后续帧交给RGB-D锚点。25米屋面距离也可触发交接，交接后不重新激活远距模板；事件原因、边界余量及最后有效分数写入`report.json`的`dino_handoff`。边界余量是开发参数，须用不同视角和独立数据验证。

斜向记录保存路径倾角、参考系洞口交点、横向误差及当前相机坐标下的3米向下进度前视点。回放以重力投影距离计算洞口位置，特征图的绿色准星使用记录的路径前视点。内部前向采图后恢复原相机安装姿态，报告使用`original_camera_pose_restored`记录恢复结果。

- `data/`保存可复用输入；`debug/`保存诊断输出；`runs/`按试验归档；`reports/`保存汇总分析；`weights/`只保存模型；`third_party/`保存引用源码。
- 每次运行目录保存输入快照、`run.h5`、`poses.json`、`signals.csv`、`report.json`、录像、帧索引与阶段日志。控制入口拒绝覆盖已有结果。
- 飞行接口使用NED米：北、东、下。RViz使用ENU米：东、北、上，转换为`(E,N,-D)`。UE导出位置为厘米，转换时同时处理单位与垂直轴方向。
- 机场运行HDF5含`pose_ned`、`action_body`和`t`；完整姿态保存在同目录`poses.json`。评价器同时识别带`pose`字段的采集格式。
- `data/metadata/targets/*.h5`只含由机场网格推导的有向包围盒属性，用于离线评价。包围盒锚点是几何近似，不能代替真实部位表面距离。

## F-14部位抵近

`configs/scenes/airport_f14.json`指定`StaticMeshActor_7888`、同一机场网格及机头、主翼和一侧垂尾区域。准备入口依据飞机前向轴和横向轴筛选实际网格顶点，取配置种子附近的表面参考点，投影生成部位ROI；机头使用准备元数据中的表面参考点。坐标用于模板准备与离线评价，控制速度仍由DINO中心和深度生成。

`prepare_scene.py --target-part nose|wing|tail`采集本次模板和远中近预检帧。主翼与垂尾分别通过纵向、横向和高度区间区分，垂尾高度下限用于排除水平尾翼和机身。长航段按速度拆分为预计不超过25秒的小段，逐段核对位置误差不超过2米。`--address`覆盖传输地址并保存到本轮场景档案。

`run_approach.py`先用全机原型截获，再在近段切到本次部位ROI原型；主翼、垂尾的ROI落点预检使用0.02归一化容差。中心深度连续3张独立帧满足停车距离后悬停。`--max-duration`限制控制时长，默认600秒；到时限、碰撞或其他保护停止会保留实际原因，只有`arrival_confirmed=true`计为到达。

部位抵近的终点评价使用保存的相机姿态和新图像DINO中心射线与飞机实际三角面求交，再按本次网格选区判定命中。机体到整机和所选部位的表面距离分别计算，选择部位的三角面要求三个顶点均满足区域条件。终点RGB、相机元数据、射线和交点保留，读取这些保存数据可离线复核，不把几何真值反馈给视觉控制。

### 共用起点的部位选择

`prepare_scene.py --common-start --reference-dir <目录>`读取任务的`common_start`，为机头、主翼和一侧垂尾使用相同的生成位置、起始位置、朝向、相机及传感器配置。准备阶段在共同位置起飞，以位置反馈稳定到起点；`common/start_state.py`核验实际位置、航向、速度与横滚/俯仰。起点位置容差0.35米、航向0.75度、速度0.08米/秒、倾斜1度。实验复位使用坐标，正式闭环的部位选择和速度不读取部位世界坐标。

共用参考目录首次采集一份整机RGB裁剪、六帧标准化统计和三个部位ROI；后续准备复用原文件，并核对场景配置与文件SHA256。网格仅在准备时生成参考ROI、初始图像核验框及评价参考点，不提供在线裁剪框。各试验目录保留自己的初始RGB、实际起点状态和共用资产校验值。

`perception/part_matching.py`复用冻结DINO。整图整机响应经连通区域提取及上下文扩展生成RGB裁剪，再对高清原图裁剪进行448×448编码；三个ROI原型共用编码器、参考图和统计量。部位softmax中心映射回原图归一化坐标后用于深度取样和控制。全图响应低于0.2或无可用区域时拒绝匹配；连通阈值为峰值减0.15且不低于0.2。裁剪由图像响应生成，没有按部位设定的坐标转场。

`run_approach.py`对保存的共同参考图和本次起始图分别核验三个部位，实际飞行前再次核验共同起点状态，从首条有效指令开始使用所选部位。保留深度停车、近距限速、高度、碰撞及失锁保护。这些保护不构成完整机体通道或动态避障验证。`viz_dump`保存原图映射后的响应、实际落点、原始匹配裁剪、裁剪响应与所选部位，可用于展示两级匹配过程；映射后的低分辨率热力图仅用于显示。

`evaluation/eval_part_approach.py --run-dir <试验目录>`只读采集终点RGB与姿态，使用对应匹配器计算新图像射线，分别评价所选部位与整机表面距离；`--offline`从保存的图像和姿态复核，不连接UE或发送飞行指令。

共同起点试验可显式使用`run_approach.py --preflight-selected-part-only`，只要求本次所选部位在参考图和起始图上均通过落点与置信度检查，三个部位的诊断仍全部保存。该选项便于分别评价不同可见性的部位；默认仍要求全部部位通过。控制报告的`matching_preflight_scope`记录放行范围，所选部位缺失、弱匹配或落点错误均拒绝抵近。

参考图应与该组试验的起始观察方向对应，采集后固定供不同部位共用；各次控制起始帧单独采集。模板ROI按特征格中心选取patch，未覆盖任何格的部位没有有效原型，诊断以`reference_patch_count=0`、`failure_reason=no_reference_patches`及无效峰值记录。所选部位无原型时拒绝抵近；选择部位独立预检时，其他部位仍可使用自己的有效原型。

`--thin-roi-refinement`为共同起点试验启用窄ROI处理。只对中心选格为空的ROI扩展一格上下文，按格子与扩展区的交叠面积加权构造DINO原型，同时固定保存原图上下文及原始部位中心锚点。DINO提供初始候选，灰度归一化相关在候选附近搜索尺度与旋转，转移固定锚点；后续搜索以最近接受的配准点为中心，保持同一侧部位。搜索半径为当前高清裁剪特征格的1.5倍，尺度范围0.5至12倍、旋转范围±15度。相关分数至少0.85、与空间竞争峰差至少0.15才接受，否则本帧停止运动；连续失锁触发悬停退出。参考图不在线更新。

窄ROI预检要求精修点位于原始部位框内，额外容差为0。速度使用精修点的滤波结果，深度在未滤波的配准锚点取样，邻域半宽按部位在深度图中的最小边长四分之一向下取整，限制在0至4像素；感知单次超过0.75秒停止控制。`point_source`、`coarse_dino_center`、配准分数/峰差、原始落点及深度取样位置分别保存。DINO热力图表示候选响应，不能用它代替局部配准落点。终点评价使用对应匹配器生成射线，几何仅用于独立核验。

终点评价默认重新初始化匹配器；`--offline --continue-tracking`以保存的最后一次有效配准尺度、角度和图像位置初始化，对独立终点图像继续跟踪。两种结果分别保留，状态初始化不读取目标几何或世界坐标。
