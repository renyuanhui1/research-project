# 项目结构与运行原理

## 模块

| 路径 | 职责 |
|---|---|
| `src/common/` | 项目路径、场景档案、日志归档、图像解码与分割ID映射 |
| `src/capture/` | 模板与起点准备、传感器采集、HDF5整理 |
| `src/perception/` | 冻结DINO、模板原型、图像全局匹配与深度点云 |
| `src/control/` | 单机抵近控制 |
| `src/debug/` | 传感器、目标对象、匹配与地图诊断 |
| `src/debug/maps/` | UE几何导出、碰撞采样、网格转换及占用栅格生成 |
| `src/evaluation/` | 位姿、包围盒及部位投影的离线评价 |
| `src/visualization/` | ROS2地图发布、匹配图与轨迹回放，以及Rerun离线多模态回放与对照 |
| `src/px4/` | MAVSDK/PX4接口与航向检查 |
| `src/coordination/` | 集中式两阶段多机协同调度中心、SQLite任务状态库与VLM评估适配 |
| `src/harbor/` | 沿海渔港三类巡检闭环（指定部位二次抵近与单机模板规划、破口测量与入室、沿线巡检与双视角录屏） |
| `src/scene_build/` | 沿海渔港道路、地块、地形外缘、建筑风损与可通行屋顶等 UE/Blender 建模与构建脚本 |

Python入口定位项目根目录，并只将`src/`加入搜索路径；跨模块使用`common`、`perception`、`control`等包导入。资产路径相对项目根目录解析，不依赖启动工作目录。`common/profiles.py`加载`--profile`或`UAV_SCENE_PROFILE`指定的JSON；默认使用`airport`。

## 沿海渔港关卡

`project_520` 中的 `/Game/CoastalHarbor/Maps/CoastalHarbor` 保存 2 km × 2 km 任务区内的 UE 对象。地面、潮滩和海面分别建模。主体建筑、船只及车辆各自拥有稳定的巡查编号，UE 标签 `Inspection` 标出 32 个重点对象。离线对象表记录编号、状态、外观损伤与位置。单机配置复用既有前向 RGB 和深度相机。安装位置、对象表和取图入口见[沿海渔港关卡](沿海渔港关卡.md)。

`harbor_street_meshes` 用米制几何制作住宅、商铺、栏杆及摊架。`harbor_streets` 复用已保存的街道和巡查对象边界布置地块，环境建筑单独放在 `Harbor/StreetFrontages`。两处重点鱼市保留原 Actor 及标签，通过替换网格更新外观。`harbor_review` 重新载入地图，检查巡查编号、建筑屋面和地面碰撞，并从保存的机位取图。

`harbor_port_plan` 以共享路口、切线路径、道路宽度和地块占地生成路面、人行道、地基、坡地和岸线。港区工业地块沿装卸路选址，两处鱼市贴近码头。住宅与公共建筑沿内陆街道选址，按谷地、山脊与果园聚落的范围赋予不同选址权重。住宅按五个聚落中心选取可连续建房的既有街段，轮流为各片区分配成排住宅，再按迁移距离匹配原住宅编号。排布同时检查路面、其他地块、田块和植被，最后按地势生成地基和通向人行道的入户路。`harbor_port` 在原 Actor 上应用变换，更新观察位，按地块计划记录的树种生成缓冲带内的植被实例。`harbor_outline.json` 以世界坐标米记录共同外边界。规划器按轮廓裁切道路、田块和树木。`harbor_perimeter` 保留地形三角面的坡度裁出曲边，从潮滩等高线与外轮廓的交集生成海面，并用裁切后的真实地形边缘生成岩质侧壁。UE 水面组件使用两倍渲染包围盒，以保持移动视角时的可见性。`harbor_review` 重载核对路面与镇界碰撞，`harbor_exposure_run` 沿鱼市立面法线连续移动相机，`check_harbor_camera` 从更新后的世界坐标布置 ProjectAirSim 的远近 RGB-D 观察位。[场景说明](沿海渔港关卡.md)

风损作为地图构建的最后一步写入。`harbor_storm_plan` 用已保存的地块、朝向和巡查编号选取受损屋面，在来源建筑下风侧、码头和潮滩布置残留物。`harbor_storm_meshes` 生成真实开口、剩余椽条、弯折桅杆和碎片组网格。`harbor_storm_apply` 在原建筑和拖船 Actor 上替换网格，依据 UE 多点碰撞查询调整散落物的位置与坡度。Windows 工程的 `SourceArt/CoastalHarbor/StormAftermath/placed.json` 保存碎片组的来源和实放坐标；编号目标仍由 `PortTown/catalog.json` 管理。


## 跨机器仿真连接

WSL与服务器237均连接Windows主机178上的UE。两端`configs/scenes/airport.json`的`simulator.address`统一填写`192.168.31.178`；入口直接读取该字段，`--profile`和`UAV_SCENE_PROFILE`用于选择档案。运行时选择一端使用完整客户端，结束并断开后再切换另一端。

ProjectAirSim通过TCP 8989传输相机等话题，通过TCP 8990处理服务请求。UE需在机场关卡进入Play；Windows入站规则允许来源`192.168.31.237`访问这两个端口。图像接收质量以实际独立帧率及日志为准。PX4还使用TCP 4560和UDP 14540/14588，飞控部署地址与链路需单独核验。

## 配置与数据流

```text
configs/scenes/<scene>.json
  ├─ configs/simulation/*.jsonc → ProjectAirSim无人机与传感器
  ├─ configs/missions/*.json → 起点、速度、相机俯角及停车阈值
  ├─ data/templates/ → 模板与特征统计图像
  └─ data/maps/ → 背景栅格、飞机三角面和精细表面体素

src/capture/prepare_scene.py
  → 已知坐标采集模板、几何投影ROI、起点布置
  → runs/approach/<id>/runtime-scene.json + scene-profile.json
  → template.json + validation-frames.npz + controller-setup.json

src/control/run_approach.py
  → 远近景匹配预检
  → RGB → 冻结DINO → 标准化 → 模板相似度/softmax中心
  → 中心滤波 + 深度 → 机体系速度 → ProjectAirSim
  → runs/approach/<id>/原始记录、双路录像、日志和viz_dump

src/visualization/matching.launch.py
  → 地图节点：OccupancyGrid + MarkerArray
  → 回放节点：viz_dump → 位姿、轨迹、匹配画面 → RViz
```

参考点坐标用于采集准备与离线评价，正式抵近的速度不由目标坐标生成。无人机位姿还用于高度保护、轨迹显示与评价。地图提供空间对照，不参与当前速度控制或障碍规避。准备过程需核对UE目标变换与保存地图一致。

地图显示由二维地面色块、背景碰撞体素和按高度着色的飞机表面体素组成。地图发布时先发送空命名空间的`DELETEALL`清除已有标记，再发送当前地图几何。

机场多目标回放向地图节点传入目标目录 `catalog.json`。地图在全局占用栅格和背景碰撞体素上叠加目录引用的 ENU 三角网格，并移除与当前目标包围盒重叠的背景体素。飞机网格按 0.25 米单元合并顶点以减轻显示负载，机库和塔楼直接使用存档网格。

## 感知、控制与记录

`Fingerprint`用统计帧计算特征均值、方差，构造整图及ROI原型；不训练编码器。远段使用整机原型，可信深度连续进入45米后切换部位ROI。图像softmax中心经指数滤波后输入控制。

主入口支持斜俯视和俯视。斜俯视100米任务远段水平速度上限3米/秒，近距12米内合速度限制0.35米/秒。停车要求3张独立深度帧满足阈值；保留高度、深度、碰撞、失锁和图像超时保护。部位匹配须通过对应准备目录的预检，各目标结果见[实验索引](../reports/EXPERIMENTS.md)。

前摄与跟随RGB为1920×1080，深度为640×360，采集请求间隔0.0333333秒（30 Hz）；默认关闭语义分割流与未用辅助传感器。多机协同另提供精简720p配置`configs/simulation/robot_quadrotor_multi_720p.jsonc`（前摄与跟随RGB均为1280×720、深度640×360、30 Hz，保留`Chase`供可视化）。跟随相机位于机后3米、上方1.5米。深度按`16FC1`米制解码，episode存储保留fp16；无效值记0。不同分辨率测距使用归一化图像坐标。录像按30FPS编码，实际独立源帧率由报告与帧索引给出，含重复帧时不能视为真实30FPS采集。

## 文件与坐标约定

`src/visualization/opening_replay.py`读取已保存记录，生成`rviz/manifest.json`和`rgbd-map.npz`，发布`/opening/map`、`/opening/markers`、`/opening/path`和`/opening/view`。点云由开发采集的透视深度与保存的相机位姿投影到ENU，按0.35米去重，不运行SLAM。`matching`模式逐项显示离线结果及9个采集位姿，不发布轨迹连线；`entry`模式发布实际坐标飞行的417条位姿轨迹，照片只在已有4个采集位置更新，并显示持有照片的时间差。回放按索引计时，保留原始时间戳，不补造连续照片；不连接仿真。

洞口开发使用`src/capture/collect_opening_views.py`按已知目标坐标采集独立开发序列，保存原始RGB、深度、位姿和运行配置；它只采集屋顶上方视图，不执行视觉抵近。入口检测到已有Drone1时默认拒绝重载；显式传`--reset-scene`会先记录已有无人机状态，再重载仿真准备起点。

`opening_replay.py --mode alignment --flight-dir <控制目录>`读取实时对准的`signals.jsonl`、RGB-D及保存的匹配图，发布每条实际控制观测的位姿轨迹和对应画面。背景点云每10组RGB-D选一组并包含末帧，使用保存的深度相机位姿投影；全部观测仍参与回放。默认按控制记录的`time_s`间隔播放，`--speed`缩放时间，循环末暂停2秒；显式传`--rate`则按索引播放。青色标记为近层平面上的投影空隙参考，蓝色标记为保存的无人机位置；不计算新匹配、不运行SLAM、不连接UE。

`render_opening_features.py`读取控制记录中的候选裁剪、固定模板、参考统计和原始RGB-D，离线重建32×32空间DINO相似度及RGB-D跟踪点。红色按`√(softmax/max_softmax)`叠色，仅用于显示；原候选平均分数仍单独核对，不把显示权重作为控制权重。绿色大十字在DINO阶段使用记录的洞口点，在RGB-D阶段将记录的水平误差投影到当前地面深度平面；密集绿色小点为RGB-D角点与LK跟踪所用的特征，包含关键帧刷新后新提取的点。重算结果核对原分数、位姿及源记录哈希，通过后由`opening_replay.py --feature-view-dir`同步播放。`--image-window`另开大图窗口，图中明确标识离线重算及当前控制来源。

`src/visualization/rerun_replay.py`在`airsim`环境中运行，不依赖ROS2与UE，将已有实验记录离线导出为`.rrd`多模态文件并可选通过`rerun --serve-web`在浏览器中交互查看。`opening`子命令读取洞口对准或入室控制目录的`signals.jsonl`、`rviz/manifest.json`、`rviz/rgbd-map.npz`及原始RGB-D帧，在统一时间轴上同步展示ENU三维点云与轨迹、特征匹配图、米制深度图（`float32`米）、高度/误差/速度曲线及状态日志；`compare-harbor`子命令读取两组沿海渔港Task 2入室目录的`summary.json`、`opening_servo_trace.json`、`nadir_overview.npz`和双视角`indoor_entry.mp4`，以原生H.264视频流、三维屋顶破口点云与起终点位移、风向箭头及同图对比曲线呈现对照结果。

`src/evaluation/eval_opening_matching.py`读取`configs/missions/hangar_opening_validation.json`，从固定参考图裁剪洞口模板，仅用参考图计算`Fingerprint`标准化统计量；验证帧不参与统计。它比较整帧DINO中心与由该中心决定的原始高清候选裁剪，输出原图像素坐标、响应和诊断图。人工洞口轮廓只用于参考图自检，响应中心不作为可通行位置；输出不构成穿越验证或飞行放行依据。

启用`--depth-geometry`时，`perception/opening_geometry.py`先把透视射线深度转换为相机前向深度，按深度分层提取封闭候选，排除与画外相连的远层。形态学归组只生成身份匹配候选，实际可见空隙保留横梁及无效深度。各候选原始RGB裁剪由固定模板的DINO空间patch对应排序；开发分数阈值以下不输出建议落点。落点的投影半径只描述当前视线下的二维空隙，不包含遮挡后的三维通道净空。该方法假设已知内参的垂直俯视深度，当前开发数据使用90°水平视场。

`perception/opening_matching.py`提供离线评价与实时控制共用的候选空间DINO排序。`control/run_opening_alignment.py`只连接已有的空中Drone1，读取实时RGB-D和相机内参，要求90°水平视场、垂直俯视、同视点及无畸变。RGB和深度均须为独立递增时间戳，配对偏差上限0.15秒、输入帧龄上限0.75秒；推理及保存之后再次核对帧龄。三帧候选连续获取后，将图像偏差乘近层代表深度换算为相机平面位移，再按该帧相机旋转转换成NED水平速度；速度计算不使用目标世界坐标或相机世界位置。

水平对准使用最高0.35米/秒、0.3秒脉冲，每次执行后发送悬停指令，再获取动作后的独立帧。定高指令保持入口读取的初始NED Z；绝对高度45—105米、相对高度漂移1.5米及起点水平半径15米作为独立保护。弱匹配、候选歧义、候选框或空隙点突变、屋面距离不足、图像过期及新碰撞事件停止试验。对准确认要求5张独立帧、至少2秒满足0.5米近似图像平面误差和0.15米/秒水平速度；这些是实验参数，不是已校准定位精度。入口保存原始RGB-D、匹配图、相机元数据、`signals.jsonl`与`report.json`，包含失败输入和最终悬停状态；不执行下降或通道穿越。

`collect_opening_views.py --alignment-start-only`用于当前无Drone1时按已知坐标准备65米高起点，只采集一组RGB-D后悬停。准备飞行与视觉闭环分开归档；控制入口不重载场景、不起飞、不解锁。

准备入口的`--camera-down-angle`指定镜头朝水平线下方的角度；斜视起点默认在目标包围盒中心的南侧，水平偏移为“65米与屋顶最高点高度之差÷角度正切”。`--start-offset-ne N E`可明确指定实验起点偏移。坐标与包围盒仅用于准备，正式控制不读取这些目标坐标。

`run_opening_alignment.py --enter`在对准确认后初始化RGB-D视觉参考系，继续下降抵近并穿过洞口。`perception/rgbd_entry.py`在洞内可见远层上提取特征，以LK连续跟踪，使用当前深度及鲁棒三维刚体配准估计相机相对参考系的位置。移动超过4米、三维残差增大或内点变少时刷新局部视觉关键帧，新特征用当前视觉变换转回同一参考系；不使用UE位置修正。残差同时在像素和米制空间检查，近景像素限值随当前深度换算。速度由该视觉相对位置及相机朝向生成，不使用UE目标位置或相机世界位置；UE高度与视觉下降量的差异仅作独立停止保护。距估计屋面25米以外仍校验DINO对应，近处由已验证的RGB-D锚点交接。

入室通道使用水平半宽1.25米的采样棱柱，从初始相机下方3.5米至估计屋面下方8米及包络余量，按0.25米采样；深度按5×5邻域最小值处理，保留横梁及无效像素。采样点前方须有超过0.3米加半个采样体对角线的测量余量。近盲区由小步动作及中心深度保护约束；已验证但随后出视野的包络点最多缓存45秒，因此此控制假设场景静止，不构成动态障碍保证。观察到障碍、无效深度、未知/过期通道或视觉失锁立即停止。

入室阶段沿完整核验通道连续发送速度指令，每条默认0.8秒并以新RGB-D更新；异常、等待或到达时实测停车。远段下降速度上限0.8米/秒，距估计屋面10米内及穿越阶段上限0.35米/秒，水平上限0.25米/秒。水平偏差超过0.35米时先修正再下降。下降到估计屋面下方8米附近后，以连续独立观测和低水平/垂直速度确认内部悬停，将FrontCamera临时转为前向采图并恢复俯视，不重载场景；检查图像近白比例与标准差，拒绝严重过曝或无变化图像。`entered`与`aligned`分别记录，停止在对准阶段不计入室。绝对高度下限8米、中心深度下限5米及视觉/UE下降量差异1.5米作为独立保护。

`run_opening_alignment.py --enter --oblique`使用斜俯视相机，要求光轴朝水平线下方40—80度，保持90度水平视场及RGB-D配准。深度先反投影为三维点，再按相机姿态提供的重力方向分层，假设候选屋面近似水平。洞口像素射线与估计屋面求交得到视觉参考系中的穿越点；洞内地面深度不作为屋面交点距离。固定俯视模板继续承担DINO候选排序，弱匹配仍停止，斜视外观可靠性需由对应图像验证。

斜向通道中心线从视觉交接时的相机位置经过洞口交点，并延伸到估计屋面下方8米；终点不使用内部世界坐标。通道以向下进度参数化，水平速度为路径斜率乘下降速度加横向纠偏。两者协调限速，水平偏差超过0.35米时停止下降；起点水平半径保护为60米。机体水平包络根据斜率扩大，以包含机体上下表面扫过的范围；深度余量为0.3米加斜向采样单元最大对角线的一半。近盲区、0.25米采样与45秒静态缓存约束同样适用，视野不能覆盖完整待检包络时停止。光轴附近5米测距保护在斜视下表示前下方障碍距离，不等同于正下方离地高度。

斜向DINO交接还依据当前候选上下文裁剪框到图像边界的归一化距离：最小边界余量降至8%或更少时，在该帧DINO身份和视觉几何一致性仍通过、RGB-D位姿和通道均有效的条件下，后续帧交给RGB-D锚点。25米屋面距离也可触发交接，交接后不重新激活远距模板；事件原因、边界余量及最后有效分数写入`report.json`的`dino_handoff`。边界余量是开发参数，须用不同视角和独立数据验证。

斜向记录保存路径倾角、参考系洞口交点、横向误差及当前相机坐标下的3米向下进度前视点。回放以重力投影距离计算洞口位置，特征图的绿色准星使用记录的路径前视点。内部前向采图后恢复原相机安装姿态，报告使用`original_camera_pose_restored`记录恢复结果。

- `data/`保存可复用输入；`debug/`保存诊断输出；`runs/`按试验归档；`reports/`保存汇总分析；`weights/`只保存模型；`third_party/`保存引用源码。
- 每次运行目录保存输入快照、`run.h5`、`poses.json`、`signals.csv`、`report.json`、录像、帧索引与阶段日志。控制入口拒绝覆盖已有结果。
- 飞行接口使用NED米：北、东、下。RViz使用ENU米：东、北、上，转换为`(E,N,-D)`。UE导出位置为厘米，转换时同时处理单位与垂直轴方向。
- 机场运行HDF5含`pose_ned`、`action_body`和`t`；完整姿态保存在同目录`poses.json`。评价器同时识别带`pose`字段的采集格式。
- `data/metadata/targets/*.h5`只含由机场网格推导的有向包围盒属性，用于离线评价。包围盒锚点是几何近似，不能代替真实部位表面距离。

[场景切换](USAGE.md#场景配置与切换)说明哪些配置需要随UE关卡、目标和地图一起准备。

## 飞机A部位抵近

`configs/scenes/airport_aircraft_a.json`指定`StaticMeshActor_7888`、同一机场网格及机头、主翼和一侧垂尾区域。准备入口依据飞机前向轴和横向轴筛选实际网格顶点，取配置种子附近的表面参考点，投影生成部位ROI；机头使用准备元数据中的表面参考点。坐标用于模板准备与离线评价，控制速度仍由DINO中心和深度生成。

`prepare_scene.py --target-part nose|wing|tail`采集本次模板和远中近预检帧。主翼与垂尾分别通过纵向、横向和高度区间区分，垂尾高度下限用于排除水平尾翼和机身。长航段按速度拆分为预计不超过25秒的小段，逐段核对位置误差不超过2米。`--address`覆盖传输地址并保存到本轮场景档案。

`run_approach.py`先用全机原型截获，再在近段切到本次部位ROI原型；主翼、垂尾的ROI落点预检使用0.02归一化容差。中心深度连续3张独立帧满足停车距离后悬停。`--max-duration`限制控制时长，默认600秒；到时限、碰撞或其他保护停止会保留实际原因，只有`arrival_confirmed=true`计为到达。

部位抵近的终点评价使用保存的相机姿态和新图像DINO中心射线与飞机实际三角面求交，再按本次网格选区判定命中。机体到整机和所选部位的表面距离分别计算，选择部位的三角面要求三个顶点均满足区域条件。终点RGB、相机元数据、射线和交点保留，读取这些保存数据可离线复核，不把几何真值反馈给视觉控制。

### 共用起点的部位选择

`prepare_scene.py --common-start --reference-dir <目录>`读取任务的`common_start`，为机头、主翼和一侧垂尾使用相同的生成位置、起始位置、朝向、相机及传感器配置。准备阶段在共同位置起飞，以位置反馈稳定到起点；`common/start_state.py`核验实际位置、航向、速度与横滚/俯仰。起点位置容差0.35米、航向0.75度、速度0.08米/秒、倾斜1度。实验复位使用坐标，正式闭环的部位选择和速度不读取部位世界坐标。准备阶段读取参考帧前使用与采集器相同的曝光等待判据：连续3帧均值低于220且标准差大于5，上限120秒，避免模板和统计量取自过曝帧。

共用参考目录首次采集一份整机RGB裁剪、六帧标准化统计和三个部位ROI；后续准备复用原文件，并核对场景配置与文件SHA256。网格仅在准备时生成参考ROI、初始图像核验框及评价参考点，不提供在线裁剪框。各试验目录保留自己的初始RGB、实际起点状态和共用资产校验值。

`perception/part_matching.py`复用冻结DINO。整图整机响应经连通区域提取及上下文扩展生成RGB裁剪，再对高清原图裁剪进行448×448编码；三个ROI原型共用编码器、参考图和统计量。部位softmax中心映射回原图归一化坐标后用于深度取样和控制。全图响应低于0.2或无可用区域时拒绝匹配；连通阈值为峰值减0.15且不低于0.2。裁剪由图像响应生成，没有按部位设定的坐标转场。

`run_approach.py`对保存的共同参考图和本次起始图分别核验三个部位，实际飞行前再次核验共同起点状态，从首条有效指令开始使用所选部位。保留深度停车、近距限速、高度、碰撞及失锁保护。这些保护不构成完整机体通道或动态避障验证。`viz_dump`保存原图映射后的响应、实际落点、原始匹配裁剪、裁剪响应与所选部位，可用于展示两级匹配过程；映射后的低分辨率热力图仅用于显示。

`evaluation/eval_part_approach.py --run-dir <试验目录>`只读采集终点RGB与姿态，使用对应匹配器计算新图像射线，分别评价所选部位与整机表面距离；`--offline`从保存的图像和姿态复核，不连接UE或发送飞行指令。

共同起点试验可显式使用`run_approach.py --preflight-selected-part-only`，只要求本次所选部位在参考图和起始图上均通过落点与置信度检查，三个部位的诊断仍全部保存。该选项便于分别评价不同可见性的部位；默认仍要求全部部位通过。控制报告的`matching_preflight_scope`记录放行范围，所选部位缺失、弱匹配或落点错误均拒绝抵近。

参考图应与该组试验的起始观察方向对应，采集后固定供不同部位共用；各次控制起始帧单独采集。模板ROI按特征格中心选取patch，未覆盖任何格的部位没有有效原型，诊断以`reference_patch_count=0`、`failure_reason=no_reference_patches`及无效峰值记录。所选部位无原型时拒绝抵近；选择部位独立预检时，其他部位仍可使用自己的有效原型。

`--thin-roi-refinement`为共同起点试验启用窄ROI处理。只对中心选格为空的ROI扩展一格上下文，按格子与扩展区的交叠面积加权构造DINO原型，同时固定保存原图上下文及原始部位中心锚点。DINO提供初始候选，灰度归一化相关在候选附近搜索尺度与旋转，转移固定锚点；后续搜索以最近接受的配准点为中心，保持同一侧部位。搜索半径为当前高清裁剪特征格的1.5倍，尺度范围0.5至12倍、旋转范围±15度。相关分数至少0.85、与空间竞争峰差至少0.15才接受，否则本帧停止运动；连续失锁触发悬停退出。参考图不在线更新。

窄ROI预检要求精修点位于原始部位框内，额外容差为0。速度使用精修点的滤波结果，深度在未滤波的配准锚点取样，邻域半宽按部位在深度图中的最小边长四分之一向下取整，限制在0至4像素；感知单次超过0.75秒停止控制。`point_source`、`coarse_dino_center`、配准分数/峰差、原始落点及深度取样位置分别保存。DINO热力图表示候选响应，不能用它代替局部配准落点。终点评价使用对应匹配器生成射线，几何仅用于独立核验。

终点评价默认重新初始化匹配器；`--offline --continue-tracking`以保存的最后一次有效配准尺度、角度和图像位置初始化，对独立终点图像继续跟踪。两种结果分别保留，状态初始化不读取目标几何或世界坐标。

### 部位重新截获的离线对照

`evaluation/eval_part_reacquisition.py`读取垂尾试验的起始图、`viz_dump`中覆盖完整原生画面的无损RGB，以及另采的终点图。固定模板、统计量、DINO和接受阈值，对比冷启动、单独的位置/尺度/角度历史、完整历史、扩大搜索范围、加密尺度及两者组合。条件扩展方法先执行默认冷启动，失败时才把搜索半径扩大三倍，保留原范围已接受的结果。历史来自当前图像之前接受的配准状态，起始图没有历史时不参与这些对照。`refine_local_image`的关键字参数`search_scales`、`search_angles`与`radius_multiplier`控制离线搜索，控制入口使用默认搜索参数。

评价几何只用于输出标注与构造合成擦除图，不提供匹配位置。起始图使用保存的部位框，中间帧以异步机体位姿及固定相机外参生成近似射线，终点使用保存的相机元数据。合成负样本擦除投影框并重新计算DINO候选；它不代表真实遮挡或留出测试。独立研究目录保存样本来源与SHA256、逐项数值、汇总、图和日志，不覆盖原飞行记录。

### 固定方案的新视角采集与评价

`capture/collect_part_views.py`使用`configs/missions/aircraft_a_tail_reacquisition_validation.json`固定距离、侧向角度、航向偏移和采样数量。入口读取现有垂尾参考与机器人配置，核对场景中飞机的位置、朝向和缩放；没有机器人时加载采集机器人，按坐标飞到各观察点，确认位置、航向与速度后保存原生RGB-D、各自时间戳及相机位姿。匹配结果不参与坐标采集飞行。取图前保存`protocol.json`及代码、参考资产哈希；完成后返回巡航位置悬停。

默认拒绝重载已有机器人。`--resume-from`仅用于本入口零采样准备中断，要求前次报告、运行配置一致，并确认原机器人仍在出生点或预定航点附近低速悬停。观察点使用上限0.5米/秒的坐标反馈消除转向与制动后的残余位移，速度与航向均满足条件后取图。起飞接口的返回值和实际飞行状态分别记录，进入巡航前须确认已在空中；碰撞或采样条件异常停止并保存中断状态。

`evaluation/eval_part_reacquisition.py --capture-dir`读取这批新图，核对采集前冻结的哈希，只比较默认冷启动、无条件扩大范围和失败后才扩大范围。每张图清空历史，使用对应相机元数据做部位射线核验；分别报告接受、接受后命中所选部位、误命中及整组观察条件的结果。合成擦除图另外统计，不能替代真实遮挡。三张同条件图像按相关样本处理，全部条件与失败图都保留。

`capture/collect_training_views.py`为学习型接受判据和局部配准准备带标签数据。位姿在飞机前向坐标系内随机采样，用`SetPose`逐帧瞬移，不执行航线飞行；相机保持固定−35度，因此样本几何与部署一致。`capture/part_masks.py`用目标网格做射线投射，按场景档案的机头、主翼、垂尾区域生成逐像素掩码，并保存整机掩码作背景与遮挡参考。部位成员由前向、横向、高度边界和以共用尾参考点为圆心的半径共同判定，半径过大时只剩分区边界起作用。掩码位姿取自图像消息中的相机位置和四元数；取图后读取的机体运动学可能落后约0.5秒，不能用于标签。掩码只依赖位姿、网格和区域规则，不读取图像。每帧同时保存原生RGB-D、相机元数据和实际机体位姿，供离线提取匹配特征或训练局部配准。`capture/rerender_part_masks.py`用保存的相机位姿离线重渲染掩码，并可按已记录的搜索块重建训练目标，改动区域定义后无需重新仿真。

## 飞机B部位数据

`configs/scenes/airport.json`是飞机B（`StaticMeshActor_7890`）的部位档案，给出机头、主翼和一侧垂尾的前向、横向、高度边界及半径，共同参考点取机头。`configs/missions/aircraft_b_approach.json`定义斜俯视准备任务，`configs/missions/aircraft_b_training_views.json`定义瞬移采样方案。准备、采集、掩码和训练入口与飞机A相同，只替换档案和任务。参考图以机头为中心时，三个部位ROI都覆盖整机裁剪中心，`thin_roi_refinement`不产生局部参考点，冻结匹配器没有候选；这批数据只用于局部匹配器的搜索块与目标，没有NCC特征。

`evaluation/eval_cross_template.py`读取带`patch_xyxy`的特征文件与HDF5样本文件或图片目录，按训练相同的（15度侧向扇区×距离档）分组重建5折。`--mode self`只用各折留出帧，复现训练时的OOF；`--mode transfer`用全部折模型推理另一份数据，用于跨采集、跨机型评价。两种模式都报告3像素正确率、峰值落在掩码内的比例，以及除以掩码等效半径的面积归一化距离，避免大掩码被3像素容差抬高。迁移结果同时混有外观、部位边界和搜索块中心三类差异，不能单独归因于外观。

`evaluation/eval_nadir_template.py`是模板条件化主线的离线粗定位基线：按采集报告的相机位姿把目标网格顶点投影到高空俯视图上，外扩裁出俯视模板，与斜视模板一起编码成整机DINO原型，在给定采集的每帧上求响应图，统计峰值与softmax质心是否落在整机掩码内。标准化统计量来自被评采集自身的抽样帧，两个模板共用。整机原型对朝向敏感，脚本对每个模板做0/90/180/270度旋转，逐帧按峰分选最高者；这一选择不使用真值。该基线只含整机一级，部位定位与接受层不在其中。

训练样本由`common/patches.py`统一读写。`extract_part_features.py --patches <文件.h5>`把每帧保存为`/<sample>/rgb_png`（256×256 RGB图像的无损PNG编码）和`/<sample>/targets/<part>`（64×64、float16，gzip无损压缩）。特征和裁剪框保存为`features.jsonl`，汇总保存为`summary.json`。局部匹配器训练、跨模板评价与标签重建共用此存储接口，也可读取PNG/NPY目录。训练仍先把样本读入内存，再按原分组与增强方法训练；接受层的逐帧分数保存在`oof.jsonl`的`scores`字段。

## 多目标分阶段抵近

`data/maps/airport_targets_20261116/`保存目标及同原点配套Actor的源网格、世界ENU三角面、变换和包围盒校验。位置与在线查询核对；飞机、机库和塔台保留完整导出三角面。

`capture/prepare_scene.py --oblique`准备整目标模板和指定部位ROI，分别保存远端、近端及8米验证图；目标坐标和网格仅用于准备和终点评价。`control/run_approach.py`从整目标原型开始，连续3帧锁定且滤波深度不大于`roi_switch_dist_m`时切换到部位原型并清空滤波状态。连续3张独立深度帧达到停车距离后悬停，再由`evaluation/eval_part_approach.py`独立取图，核验匹配射线是否命中指定部位，报告机体到网格的距离。一个目标完成停车和终点核验后才进入下一目标。

实验目录`runs/approach/20261116-coarse-to-fine/`按清单顺序保存各目标配置、准备数据、控制记录和终点评价。机鼻使用参考点球域，其他部位使用配置中的前向、横向、高度边界及半径选择局部几何，并以区域内最接近种子的网格点作为参考。`approach_axis=rear`从目标后方接近，`negative_side`从负横向接近，默认从正横向接近；方向选择不改变部位区域的坐标定义。非机鼻部位的近端预检容差为归一化坐标0.02，远端整目标预检容差为0.1。

标准单向抵近第一次有效深度进入`close_range_m`后，合速度保持不超过`close_speed_mps`直到该次运行结束；后续背景深度跳变不恢复巡航速度，失锁仍停车。报告`close_speed_latched_at_step`与逐帧`close_speed_latched`记录近端限速状态，开始新运行时重新初始化。

部位可用`part_template_distance_m`及`part_template_roi`指定独立近端模板；标定距离列表须包含该参考距离和`close_range_m`。准备入口保存近端原生RGB、相机元数据和近端切换距离的验证图。控制先匹配远端整目标，原45米条件切到整目标模板中的部位ROI，进入`close_range_m`后停车、清空滤波并切到独立近端部位原型；编码器与未标注标定统计共用。各尺度分别预检，`report.json`记录`part_template_switch`，终点评价按`controller_args.part_template_active`使用实际末端原型；部位几何保持独立。未配置此项时使用整目标模板中的部位ROI。

终点评价图的区域框使用相机前方的有限投影点，坐标裁剪到图像范围；没有可绘制点时省略区域框。射线求交和表面距离使用完整选定几何，绘图筛选不参与数值评价。

局部部位可设置`template_roi_fraction=[x0,y0,x1,y1]`，相对于投影局部框选择实际匹配纹理；它不改变几何区域、参考点或独立终点评价范围。`run_approach.py --handoff-on-roi`在整目标到部位的三帧切换条件满足时悬停，报告`handoff_ready=true`及`arrival_confirmed=false`，供屋顶洞口控制器接管；该模式预检远端整目标，局部洞口由接管入口独立验证。

`run_approach.py --roof-handoff`使用实时RGB-D的重力投影分层估计屋面近层，将垂直距离按相机朝下分量换算为光轴距离后滤波，连续3帧进入45米时交接；地面或洞底深度不会代替该屋面距离。分层缺失则停止，屋面垂直余量低于15米也停止。屋顶专用入口继续完成洞口匹配、视觉锚点和通道核验，坐标不进入该感知与速度计算。

`capture/prepare_opening_handoff.py`读取已确认`handoff_ready`的粗定位记录，连接现有无人机，只调整相机安装姿态并保存新RGB-D及运行配置，不发飞行指令。随后`control/run_opening_alignment.py --enter --oblique`在此配置上进行真实洞口匹配、视觉锚点跟踪与自由通道核验；进入状态需另行检查目标内部位置及观测图。

`evaluation/eval_opening_entry.py`对屋顶入室的终点单独取图和读取机体位姿，使用目标档案中整组Actor的导出网格检查机体是否位于凸包占地和高度范围内、是否低于入室锚点估计的屋面，并检查室内照片及已确认悬停。凸包用于当前矩形机库组成，不能解释为任意凹形建筑的精确室内分割。网格、目标坐标与机体位姿只用于独立评价，入口不发飞行指令。

部位配置的`template_anchor_half_size`以模板归一化坐标指定参考点周围匹配框的半宽，并裁剪到原局部框内；参考点投影仅在模板准备时使用。`preparation.statistics_source`选择`all_calibration`或`far_start`，后者只用未标注远端标定帧计算标准化统计，全部采集帧同时保存在`all_calibration_rgb`供审核。

标准准备入口为前相机锁定滚转和俯仰，航向跟随机体，安装俯角取任务参数；元数据中的实际姿态用于检查固定俯角是否生效。

标准斜视准备将匹配验证图保留为相机原生RGB分辨率，特征模型执行与在线相同的缩放流程；用于标准化统计的采样图另外保存。模板元数据保留参考及起点相机姿态，供检查视角和投影范围。

局部部位可用`approach_bearing_deg`设置相对于目标前向轴的连续接近方位，正角朝正横向旋转；该值优先于`approach_axis`，不改变区域的前向、横向定义，供与参考观察面一致的航点准备使用。

屋顶入室允许在对准和下降中按视觉路径移动，不以固定累计水平位移截断；水平观察模式保留15米范围。执行时限由任务参数给出。室内前向照片采集后，使用运行快照中的安装姿态恢复相机，保持交接俯角。

控制入口停车使用世界零速度及实测机体航向保持，连续低速和低偏航角速度后才确认悬停；屋顶交接前10米内合速度限制为0.35米/秒。相机交接入口另行确认速度低于0.1米/秒、偏航角速度低于0.02弧度/秒，且航向与粗定位终态相差不超过5度。

洞口入口可用`--whole-target-run-dir`复用已确认交接的整目标模板及标定统计。DINO先定位整目标，再用真实RGB-D近层连通区域核验破口边界与定位点属于同一屋面，选择任一闭合破口，连续帧按框重叠保持选择。此模式不辨认指定洞口，也不以俯视洞口模板判身份。投影空隙尺寸只在对准后准备下降时检查，屋面上方的水平对准允许从较小可见开口开始；三维通道核验仍独立执行。

斜视空隙的中心和半径在重力定义的水平屋面上计算：将原始可见空隙按相机射线投影为米制平面，再做距离变换，结果映射回原深度图。变换不填补横梁、无效深度或未知区域；屋面投影净空不等同于三维下降通道净空。

梁间空隙的精对准点选择米制空隙内最靠近几何中心的真实可见点，净空半径按该选中点的距离变换值计算。控制不逐帧追逐最大净空点；下降前仍独立核验完整三维通道。

任一破口模式将同一屋顶破损组中的真实可见空隙按连通性分开；首次按米制净空选择，随后按上一帧自由空隙框的重叠保持同一个梁间通道。视觉锚点在该自由空隙内初始化，三维通道核验仍使用完整实际深度。

任一破口入口初次全图确认屋面，后续身份查询使用当前对准区域三倍大小的图像裁剪，坐标映回原图；破损组水平阶段用组框，梁间精对准与入室阶段用实际空隙框。`--resume-from`只借用保存的图像区域，要求同一整目标引用及相机配置、机体相对保存终态位移不超过0.5米、航向不超过2度；下降记录还要求高于已观测屋面至少`--min-roof-range`米，默认15米。入口重新获取独立帧、屋面及完整通道，不恢复到达计数、旧视觉位姿或通道缓存。机体位姿只核对图像区域可用性及重新获取的高度条件，不产生目标导航坐标。

任一屋顶破口模式在投影对准后，以当前真实RGB-D逐一核验该屋面的候选下降通道，拒绝有障碍、未知或无效深度的路径，采用完整核验通过的路径；通道可与光轴形成夹角。报告分别保存投影对准候选、实际入室候选及尝试结果，不能把两者混称为同一光轴对准点。视觉锚点与新路径再经3张独立帧核验后才发送入室速度。`--entry-pulse`配置已核验通道上的指令时长，速度、相对位姿跳变、通道更新和帧龄保护继续生效。

通道规划还在同一自由空隙内检查圆心邻近、按两倍通道采样步长偏移的交点，偏移后仍需属于原可见空隙且通过完整三维射线核验；同候选优先选择最小观测余量最大的路径。证书保存扣除原安全余量后的`minimum_observed_margin_m`，用于比较可行路径，不改变原接受条件。

`--vertical-entry`在近端保持初始高度，水平速度连续更新；对准等待和到达时实测停车。任一屋顶破口模式先对准整个破损组的米制几何中心，相机按视线逐步从斜视转为垂直，每帧最多改变2度。组中心只作屋面上方航点，可以投影在梁上，不作为自由通道。达到0.5米水平误差并确认相机接近垂直后，保存`roof_group_alignment`，在该组中选择投影净空最大的实际梁间空隙，保持垂直相机重新取得3张稳定帧并精对准；这一阶段继续要求实际空隙半径。精对准停车后才核验完整竖直通道并交给RGB-D锚点下降。`signals.jsonl`的`alignment_phase`区分`roof_group`、`free_gap`和`entry`。目标位置来自当前图像射线与屋面，不读取目标世界坐标；斜视光轴与屋面的交点不作为停车位置。

屋面身份在初次获取时由当前DINO点与近层连通性确认；独立帧获取完成后，已验证自由空隙可通过框重叠率至少0.5维持原破口组归属。该分支仍需原身份分数门槛及2米点位连续性，报告identity_association，适用于局部视角中身份点移入边界相连的洞内地面；初次获取不能仅凭跟踪框建立身份。

整目标屋面获取的最初3帧均查询完整图像；仅在身份已通过独立获取后才切换到空隙周围局部查询。`roof_identity_verified`记录这一状态，图像区域重新获取仅在此前已验证时复用连续身份；未验证记录仍执行3帧全图确认。

初次获取尚未凑齐连续3帧时，候选或点位变化会清零稳定计数并继续悬停，报告`acquisition_resets`。连续3张独立帧稳定后才发水平速度；确认后的2米点位跳变仍停止，梁间精对准及未通过视觉锚点区域核验的组跟踪还要求框重叠率至少0.5。

初次提取排除与画边相连的远层。已验证空隙移动到画边时，只允许当前真实远层连通区域与上一帧框重叠率至少0.5的候选继续跟踪，标记`tracked_boundary_gap`；不补齐画外区域。合并外部地面导致重叠不足、点位跳变或身份分数不足仍停止，下降前重新使用实际深度核验完整三维通道。

破损组水平阶段同时保留已验证的组框与空隙框：满足任一框连续性的真实触边部分先纳入可见区域，再与闭合部分归组。进入梁间精对准后只用选定空隙框，避免底部小空隙的跟踪范围裁掉同组中央大破口。

破损组获取连续3帧后，将其上方航点固定在该帧相机坐标中，用近层屋面RGB-D特征估计相对相机运动；后续关键帧补点继续使用当前近层屋面掩码，保持原配准残差、点数、相对位移和旋转保护。实时几何仍用于屋面身份及区域连续性，控制航点不随分割区域合并而重算；相对旋转与实际相机姿态差超过3度停止。`roof_group_visual_anchor`保存锚点，逐帧`group_visual_anchor`保存质量。梁间精对准使用当前真实空隙，下降另行初始化视觉锚点与通道，不复用组水平段的旧缓存。

已验证视觉锚点的投影仍位于当前匹配破损组掩码内时，组框可因分裂而收缩，记录`region_continuity=visual_anchor_inside_current_matched_group`。这一路径仍要求原DINO身份分数、相对配准质量、相机姿态一致及2米航点连续性；不满足区域条件时继续要求0.5框重叠。它不用于梁间精对准或下降通道判定。

## 目标库与俯视模板

`capture/build_target_catalog.py`按`configs/datasets/airport_targets.json`读取资产核对记录、已保存的垂直俯视图、世界网格及已验收的部位定义，离线生成`data/templates/airport_targets_20261116/catalog.json`和每目标的模板、整组掩码及部位掩码。主体由核对记录确定，组成取导出清单中同原点Actor，包含机库钢梁、门和塔台雷达；不把场景档案里的地图显示Actor清单当作目标组成。

模板按整组网格投影外扩裁剪，保存相机位姿、裁片内参、世界零高度平面分辨率及完整覆盖检查。掩码对最近的整组网格表面射线求交，计入自身遮挡；几何投影框与实际可见部位分别记录。没有可见部位时保留空掩码，不能把投影框当成可见纹理。原始核对图没有实测深度，外部遮挡未核验；屋面区域掩码不表示自由开口或通道。

`catalog.json.splits`保存按目标划分的主体外观、塔台类别及机库同网格实例协议。外观与类别协议按主体网格资产分组，复制体不能跨分区；实例协议允许同源网格，仅评价换位置和组装背景。各协议独立训练，验证集用于阈值及模型选择，测试目标的给定模板可输入推理，测试搜索图和标签不能拟合权重、统计量或阈值。目录中保存输入与输出SHA256；所有目标此前参与过DINO/RGB-D开发，划分只约束后续模型训练，不代表未经查看的新资产。

## 多目标斜视采集

`capture/collect_target_pilot.py`按`configs/datasets/airport_pilot.json`从目标库的主协议训练目标生成距离与方位组合。采集要求当前场景无机器人Actor，临时加载无物理观察相机，核对目标及配套Actor的实时位置、旋转和缩放；固定35度俯角逐点设置相机位姿，等待独立、配准、曝光稳定的RGB-D后采样。结束移除观察相机，不执行无人机飞行。坐标用于采样和标签，不构成视觉控制或连续飞行验证。

标签在深度相机分辨率上对整组网格射线求交。实测透视距离与网格距离一致时保留目标及所选部位；实测更近的前景使目标像素转为背景；无效深度或实测明显更远的几何不一致区域标为未知，不作背景监督。容差为协议中的绝对米值加一个原生float16量化步长。部位标签只取主体网格，整目标标签包括配套Actor；屋面区域不作为自由开口。

每帧在`data/captures/airport_targets/20261117-pilot/samples.h5`的同名组中保存原生RGB的无损PNG字节、gzip压缩的float16深度及uint8标签；`metadata_json`保存实际相机位姿、时间戳和采样条件。`assembly_mask`、`part_mask`、`valid_mask`、`occluded_mask`、`geometry_mask`分别表示可见目标、可见部位、可用监督、前景遮挡和未经过实测过滤的网格投影。图像与标签可为不同分辨率，报告记录各自尺寸。回读校验通过才将采集标为`completed`，各次实际样本与异常保存在报告及日志。

`configs/datasets/airport_multitarget.json`使用同一入口按目标保存分片，在12—150米的四个距离层随机采样，扰动航向及高度；飞机覆盖前方半圆，建筑覆盖全方位，塔台参考高度分层。各目标的样本数量由所属分区配置，不按帧拆分目标。`--resume`核对协议、目标库和已完成分片哈希，继续当前分片，并记录每段采集的代码哈希。

训练搜索图中属于验证/测试主体网格的已知目标，以及当前训练目标的同源复制体，以投影包围盒标记为`ignored_mask`；验证图只排除测试主体，测试图不擦除。原始RGB保留，特征提取前才把忽略区替换为固定均值色，同时移除这些区域的监督。该操作是数据准备使用的几何过滤；包围盒可能覆盖邻近有效区域，模型不读取包围盒、目标坐标或相机位姿。

`capture/label_target_context.py`读取已保存的训练RGB-D和相机位姿，对训练目标的完整组成网格统一求最近表面，再用实测深度核验，生成同画面其他训练目标的实例标签。未知及已擦除区域不作监督；同源复制体有多个可见实例时不新增该组正例，避免身份歧义。输出仅含标签、来源哈希及报告，不连接UE或复制RGB-D。float16最大有限值的深度容差使用向下量化步长，避免向上步长溢出成无穷大。

## 模板条件化整目标定位

`training/extract_template_features.py`将搜索图及俯视模板编码为冻结DINOv2 ViT-S/14特征。输入缩放到448×448，缓存32×32个384维特征；模板旋转、亮度及留白组合保存在独立特征库。原生目标掩码用于最终落点核验，64×64面积重采样标签用于训练；输入、权重及特征缓存均有SHA256。

`perception/template_matcher.py`用共享投影把模板与搜索特征映射到64维，模板汇聚为8×8后进行交叉注意力，融合查询、上下文及相似度，再卷积解码64×64定位图。定位损失包含有效像素内的空间分布及目标存在性；同一搜索图配正确、错误模板，在已知目标像素上增加响应差异损失。未知区域不参与这些损失，前向只接收图像特征。

`training/train_template_matcher.py`按目标库的协议训练，标准化统计只取训练搜索图的有效像素。正例配对应目标模板；负例模板须来自不同主体网格，且该网格所有已知实例均位于扩张视锥外。对照为相同编码和统计下的单朝向/四朝向DINO原型，以及不接收模板的搜索图定位器。定位器优先按验证集在指定接受精度下的有效正例召回选择，再按正确落点分数的AUC和正例宏平均命中率打破同分；错误模板接受计为错误。

`context_labels`为条件化模型增加同一搜索图配不同可见目标模板的正例，损失使用请求目标自己的掩码；无模板对照只使用原目标任务并按正例命中率选模。额外标签与原始HDF5及特征的哈希绑定，不从验证图生成训练监督。

独立置信度头使用训练目标间按主体网格分组的交叉拟合预测：每折排除留出查询及模板组，用拟合查询重新计算标准化统计，按固定轮数训练，再预测该折留出查询。置信度头只拟合这些折外预测的落点正确性，同时保留不带学习头的图像存在性分数作对照。共享缓存可能含内层留出主体的偶然背景，内层划分只保证查询/模板排除；外层训练图对验证主体的擦除仍独立执行。

`evaluation_partition=validation`只打开训练、验证特征分片，不使用测试搜索图。验证集同时用于开发选模和阈值校准，结果标为开发结果；权重和阈值固定后，独立测试须另行配置数据。阈值不能拆分同分组，未找到达标的非空接受集时拒绝全部；开发验收的最低有效召回由配置给出。

输出目录保存权重、训练曲线、配对清单、交叉拟合折与预测、验证选择、逐对预测、按目标/类别/距离的指标及代码和配置哈希。每个定位器共用一份权重，存在性及交叉拟合置信度各保存自己的阈值和指标。它评价整目标离线定位，部位精对准、连续飞行及控制接管需要另行验证。

`evaluation/plot_template_comparison.py`只读已保存的指标与预测，绘制训练曲线和固定顺序的正负配对示例，并记录选图清单。

### 候选裁剪的模板核验

`perception/template_verification.py`从粗定位响应峰所在连通区生成候选裁剪，保留原始RGB细节并补方后送入冻结DINO。候选与四朝向模板进行互近邻图像块对应，以二维仿射一致性统计匹配数量、相似度、覆盖范围和残差；RGB局部核验使用SIFT描述子、唯一性比值及同样的仿射统计，补充较细纹理。裁剪及核验只读取图像和响应，不读取目标坐标、网格或查询标签。

`training/train_template_verifier.py`使用按主体网格分组交叉拟合的粗定位器生成训练候选，以固定粗定位器生成验证候选。裁剪特征的标准化统计只用训练帧的有效区域。几何分数、线性接受层和小型接受网络作对照，学习接受层只拟合训练候选的落点正确性；阈值仍由验证目标校准。原生RGB不复制，裁剪特征在内存中处理，输出候选框、统计特征、折划分、权重及来源哈希。

`verifier.pt`包含固定粗定位器、接受层、标准化统计和核验配置；`comparison.json`保存各分数的开发指标，`selection.json`记录验收结果。该核验验证模板与候选的对应关系，不训练部位定位，也不构成连续飞行验证。

`TemplateVerifier`加载冻结产物，`set_reference`接收RGB模板，`predict`接收RGB搜索图，返回归一化候选点、裁剪框、分数及接受标志。拒绝时仍返回候选用于诊断。它核验一个候选，不在整图枚举其他候选或发送运动指令。

编码与粗定位沿用配置的计算批量；单帧和尾批通过重复填充维持相同算术路径，填充项不进入标签或统计。缓存签名记录编码批量及精度。校准阈值放在完整接受分数组与下一拒绝分数组之间，保持选定接受集并留出浮点舍入余量。

### 接受分数诊断与候选覆盖率

`evaluation/eval_template_selection.py`复用冻结核验器的配对、分数及44维对应特征，按目标、距离、可见面积和遮挡统计分数分布、AUC、直方图重叠及接受精度的Wilson区间。验证分数来自保存的开发预测；训练分数由现有接受层作用于折外粗定位特征得到，接受层本身拟合过这些特征。RGB内点数由保存的内点比例和重提的SIFT描述子数量恢复。部位掩码面积仅描述任务部位，不是损伤差异标签。

覆盖率模式重放三个按主体网格分组的折外粗定位器，在响应局部峰值上按裁剪框IoU进行NMS，比较配置指定的K值。图像候选生成不读取标签；637张训练图的实例标签只用于事后计算峰值命中及裁剪覆盖。K=1须复现保存的点和框；分别报告原目标和同图其他目标。该模式不训练接受层、不调整阈值，也不提供独立测试结论。

### 全目标粗定位监督对照

`training/train_scene_proposals.py`复用`train_localizer`、冻结特征和既有折划分，比较原目标监督与按实例平衡的监督。后者把每个可见实例的有效掩码分别归一化，再等权合并；不改变网络、损失、有效区域、采样查询或优化参数。每折只增加拟合目标组的同图正例，留出目标不作新增正例。既有缓存可能含内层留出主体的偶然背景。

每个种子中的两组使用相同初始化、查询顺序和固定训练轮数，不通过验证结果选轮数。种子对应既有基线时比较模型参数以检查复现。评价沿用局部峰值、裁剪IoU NMS及原生掩码，并按原目标、其他目标、面积及请求目标所属拟合/留出组报告。各种子的覆盖率分别保存，以配对差值及种子间标准差汇总，不把重复帧池化为独立样本。

### 固定预算的候选融合

`evaluation/eval_proposal_fusion.py`读取配对训练保存的候选，按固定源内排名顺序合并两路输出。原模型优先交替、全目标模型优先交替及原模型首候选加全目标补充三种顺序均不比较跨模型原始分数，也不读取标签。跨路用同一框IoU阈值去重，被抑制候选不占预算槽位；缓存耗尽时保存实际数量，不补造候选。

评价复用原生掩码及拟合/留出组口径，单路基线须复现源指标。融合候选保存来源、源内排名及抑制记录；单路候选直接引用既有文件。各种子结果及配对差值分开保存。耗时模式对一张RGB只编码一次，两路定位器共享特征与归一化统计；包含缩放、传输、定位头、峰值生成及融合，不含文件读取、离线擦除、模板核验、深度及控制。

### RGB-D俯视重建与免训练匹配

`perception/birdseye_matching.py`按深度像素中心生成单位相机射线，以实测米制射线距离反投影，并用相机自身姿态旋转到NED。查询点云减去了相机位置，重建右为东、下为南的局部正交俯视图；不需要目标坐标、网格、标签或相机水平位置。局部范围、有效射线距离、地面分辨率和图像最大边长由评价配置指定。超出像素预算时增大地面分辨率，同一栅格保留最高的已观测表面，以源像素足迹补齐小空隙，并保留每个输出像素的原图索引。斜视中未看到的屋顶、背面和被挡表面无法恢复。

SIFT分支使用RootSIFT描述子、双向比值匹配和二维仿射RANSAC；重复移除内点可生成多个候选，按内点数、内点比例和模板覆盖排序。尺度和朝向通过对应点估计，俯视模板保持原成像透视，不使用目标高度修正。DINO分支冻结DINOv2，对L2归一化特征的四朝向模板均值计算余弦响应，按有效像素支持及特征格NMS取峰。两者均选取实际观测像素，俯视落点回映到原始图像后才评价。

`evaluation/eval_birdseye_matching.py`在相同训练、验证RGB-D上同时运行原斜视与重建俯视的两种匹配器。沿用已有正负模板配对，只用训练配对校准最高排名候选的接受阈值；无满足精度的阈值时全部拒绝。验证、训练同图多目标及历史折内留出请求分别统计，测试查询图保持封存。标签及目标参考点只在候选生成后用于原生掩码命中、距离分档、误指其他可见目标和投影范围保留比例。

输出登记、输入与代码哈希、逐模板候选、逐请求命中、校准、耗时和固定顺序示例。每个请求模板拥有K个候选；历史粗定位是每张图共K个候选，虽然可复用相同请求分母，预算分配及模板条件不同。耗时包含该帧全部请求模板，另列俯视投影耗时，不等同于单模板在线控制延迟。

评价支持逐帧检查点和分批续跑，恢复时核对原始输入、配置与匹配模块哈希，编排代码记录在续跑历史中。完整候选可复用，完整帧的判分与计时不重算；仅保留候选而未写检查点的中断帧重建判分，缺失匹配计时不计入耗时汇总。

### 米制模板搜索、多候选核验与影子观察

`perception/metric_birdseye.py`把模板长边缩放到配置指定像素数，并同步调整其米/像素；查询点云以相同米制分辨率建立重叠图块，遍历全部有观测的图块。模板尺度来自目标库的地面分辨率，查询只使用RGB、实测深度和相机姿态。每个图块做SIFT对应及仿射核验，候选按分数排序并在米制空间去重，落点回到实际观测的原图像素。模板地面分辨率定义在世界零高度平面，不会消除高起表面的透视变化。

`perception/multicandidate_verification.py`共享一次整图DINO编码，运行原目标监督与全目标监督的定位头，以原模型优先交替、框IoU抑制生成固定预算候选。实时推理路径对整图、定位头及候选裁剪采用无填充前向，以线程池将候选RGB的SIFT特征提取与GPU裁剪编码重叠，并在GPU上直接完成DINO与SIFT相似度矩阵的`topk(2)`及互近邻筛选（仅将互近邻点传回CPU执行仿射RANSAC）；另提供`score_candidate`接口针对单个已选候选向其他模板打分。每个候选提取DINO和RGB对应的44维特征，线性接受层针对请求模板打分并选择集合内最高分。训练查询使用其留出折；验证、测试和影子观察使用配置指定的同一个部署折。训练候选中的未知标签不拟合，每个请求的有效候选总训练权重为1。裁剪标准化统计沿用训练缓存，不能称为严格的端到端嵌套留出。

`evaluation/run_airport_completion.py`执行登记、米制开发实验、候选特征提取、训练数组导出、验证校准、冻结与测试评分。阈值针对每个请求的候选集合最大分校准，整组同分同时接受或拒绝；没有达标的非空接受集时全部拒绝。冻结清单绑定配置、源代码、粗定位权重、接受层、DINO权重及实现、实际模板文件和开发特征。测试入口先核对冻结清单。已使用过的测试查询只能标为固定方法复评，不能重新称为独立留出。

`perception/shadow_verification.py`由`run_approach.py --shadow-verifier`加载，支持以`--verifier-target-id`指定本次观察的目标模板（未指定时取配置文件默认值），以单个后台工作线程旁路观察RGB。忙时跳过新观察，返回的预测不参与速度、停车或保护判断。按配置要求连续接受并限制帧间间隔，输出确认标志；保存原生RGB-D、传感器时间差、候选、分数、耗时和确认状态，异常写入控制报告。标签与目标位置仅在飞行后用于核验，推理不读取它们。影子观察与控制共享GPU，其资源竞争通过本轮时延和完整控制记录评价。

影子线程从传感器缓存选择最新的未使用RGB-D对，分别要求RGB和深度时间戳递增，时间差不超过`shadow.max_sensor_skew_s`，RGB相对最新帧的年龄不超过`shadow.max_frame_age_s`。无合格帧对时跳过并计数，控制器仍独立选择自身输入。准备器的`--approach-bearing-offset`只旋转进场方向，部位参考区域仍按目标物理朝向构造。

控制停车分为速度归零、连续保持和停止发指令后的被动观察。`stop_hold_records`保存动作返回、机体位姿、速度及相对稳定停车点的位移；`stable_stop_verified`表示保持和被动观察均满足位移门槛，`arrival_confirmed`表示控制循环触发距离停车条件。正常结束后直接保存数据；失败时执行并记录清理悬停及其异常。几何终点评价另行读取实际机体与图像，和控制停车状态分别报告。

可见部位闭环验收使用共同起点入口，`CroppedPartMatcher`先根据整机响应裁出RGB，再在裁剪中匹配模板指定部位，将落点换算到完整画面供原控制律计算速度。试验附带的传感器记录器在原订阅回调之外保存RGB、深度和碰撞消息的到达时间与元数据，输出`sensor-arrivals.jsonl`；首帧可见性、部位匹配运动、持续停车和独立照片核验结果保存在`end-to-end-audit.json`。

`perception/active_verification.py`通过`run_approach.py --active-verifier`接入主动控制。冻结的多候选核验器读取目标库中的俯视模板，选择目标候选并按冻结阈值判定接受。连续接受满足配置后，所选候选框直接传入`CroppedPartMatcher.query_all(box=...)`作为部位搜索区；该路径使用传入框计算局部响应。模型拒绝或确认不足时返回失锁状态，控制指令为零。推理后还以机体与图像时间戳计算输入年龄，超出运行配置的`max_input_age_s`时停止运动。部位精定位使用共同起点准备的斜视参考及ROI。

斜视分阶段任务也通过`--active-verifier`指定冻结清单，并用`--verifier-target-id`选择图库实例。远段使用连续确认后的新模型候选点计算运动，`phase=far_whole`，可视化响应为稀疏候选分数。满足原距离交接条件后，近端首帧检查最近模型确认并记录其`model_record_index`，后续以准备好的部位ROI匹配控制，`phase=near_part`。机库可通过原有屋面交接选项将确认后的任务移交给屋面控制入口。分阶段预检核对实际使用的部位参考，远段接受与图像时效在新模型运行时核验。

主动入口核对权重、推理代码、目标ID与场景Actor，并记录俯视模板、部位参考和统计输入哈希。`active-records.jsonl`保存候选、分数、确认状态、搜索框、部位点、输入年龄及指令是否已下发，`active-inputs.h5`保存对应原生RGB-D。`model_inference_performed`标记该帧是否执行新模型，`near_admission`保存分阶段近端的放行依据。控制报告中的`active_verifier`标明定位与运动许可来源，`approach_command_results`保存动作返回。`whole_peak`对应核验分数，`peak`在整目标阶段使用核验分数，在部位阶段使用部位匹配分数。独立评价分别核对新模型候选与实际部位控制点，并检查非零指令的放行依据及输入时效。

主动核验离线回放从保存的原生RGB-D和时间戳复算核验分数与部位匹配。裁剪对照在同一帧上复用全图候选、参考、权重与阈值，按相邻候选框重叠关联来计算对照裁剪。确认与恢复回放记录何时满足继续抵近的条件，原飞行轨迹和深度保持为已记录的输入。场景几何用于选取视野外负例和事后评价部位点。实验目录保存输入登记、逐帧结果与验收汇总。

### 分级运动许可与时序证据门控

`perception/graded_gating.py`提供独立于单帧硬阈值的三级门控组件，所有在线计算均不读取目标世界坐标：

- `DistanceBinCalibrator`：基于纯NumPy保序回归（PAVA）按查询图观测距离分档拟合单调概率，仅在训练目标折外请求上拟合，将单帧核验分数转换为带上下界截断的对数似然比（LLR）；在线分档使用候选点实测深度。
- `SpatialTracker`：仅利用相邻帧相机相对位姿变换`ΔT`与候选点深度，将上一帧候选三维点重投影到当前帧，计算射线夹角与重投影落框状态，维护连续时空一致计数。
- `GradedGate`：按实测深度区分远段、中距离与近段交接。远段在时空一致且累积LLR高于低门槛时仅放行限速推进，并按相机位移对静止帧证据降权；身份确认在配置距离区间内通过SPRT上界及同类不同网格（`appearance_group`不同）模板的相对logit裕量完成，未确认前禁止放行近段部位交接，触发SPRT下界则进入拒绝悬停。
- 在线闭环接入：当冻结清单配置`graded_gating.enabled=true`时，`ActivePartMatcher`加载对应校准器与同类不同网格模板库，在确认距离区间内仅对选中候选调用`score_candidate`计算相对裕量；`run_approach.py`传入当前帧相机元数据、深度帧与时间戳，按`speed_cap_mps`执行分级限速、在确认前阻止近段交接，并在`identity_rejected`时停机悬停。未启用时保持原连续三帧阈值路径。

## 冻结视觉骨干的模板匹配对照

`evaluation/eval_dino_backbones.py`在相同RGB、俯视模板及部位ROI上比较配置中的冻结编码器。它直接在整幅查询图上计算模板原型相似度，单朝向及四朝向分别报告；四朝向按响应最高分选择。整目标原型使用全部模板特征，部位原型使用目标库固定ROI内的特征格中心。模板补方及旋转同步变换ROI，俯视不可见或没有覆盖特征格的ROI记录为不可用，不补造部位纹理。

每个编码器独立以训练图有效像素拟合标准化统计；验证图和标签不拟合统计。输出同时记录沿用在线坐标定义的softmax中心与特征格峰值，主指标为中心落在原生可见掩码内的比例；部位误差除以掩码等效半径。错误模板由固定配对清单给出，阈值在开发验证集校准。查询掩码和坐标只用于准备与评价。

`reference-state.npz`保存标准化统计及参考原型，不复制原始RGB或全量特征。`benchmark`阶段在控制端测量单帧编码和整目标、部位匹配耗时，填充至配置的编码批量以保持算术路径，计时包含图像缩放与设备传输、不含文件读取。DINOv3直接加载官方骨干及本地权重，不导入分割或检测任务模块。

`evaluation/eval_dino_matching.py`使用相同图像、编码器和配对，对通道标准化后L2归一化、仅L2归一化，以及不同落点计算方式做消融。原型方法分别计算边界坐标加权中心、格子中心坐标加权中心、峰值、配置温度的加权中心和峰值邻域内的加权中心；坐标定义与概率聚合分开评价。标准化统计复用骨干对照的训练统计。

逐块方法在完整斜视图与四朝向模板之间计算互近邻对应，可使用二维仿射RANSAC筛选一致匹配。整目标锚点为模板中心，部位锚点为指定ROI内特征格中心的均值；从允许的对应中选取最靠近参考锚点的已观测匹配点，不投影补造未匹配部位。仿射分数结合内点数量、相似度、覆盖范围及ROI支持。查询图的掩码只参与事后评分。输出保留所有设置、逐对落点和缺失预测，分别报告开发集原始命中最优及可靠接受最优设置。

## 多机两阶段协同勘测中心

`src/coordination/` 实现“中心决策、分机执行”的集中式两阶段多机协同勘测骨架（初查 → VLM初评 → 按需复查交接 → 次轮补拍 → VLM复评），各目标独立推进，不依赖全部目标同步完成：

- `coordination/store.py`：使用单文件 SQLite（WAL 模式）维护 `missions`、`targets`、`uploads`、`recheck_tasks`、`assessments` 和 `events` 六张表。通过 `UNIQUE(mission_id, target_id, stage, image_id)` 保证图像回传幂等去重，通过 `UNIQUE(mission_id, target_id)` 保证每个目标最多只创建一次复查任务；图像上传与无人机返航状态分字段记录，中心能区分“照片已收到”与“飞机已返航”。
- `coordination/vlm.py`：定义统一的 `BaseVLMClient` 接口，提供离线单测用的 `MockVLMClient` 和对接 Ollama `/api/chat`（支持本地 HTTP 或无状态 SSH 代理连接 237 服务器的 `qwen3.5:9b`，默认 `think=false`）的 `OllamaVLMClient`。模型只接收中性目标编号（如 `OBJ-A`）、中性图像编号与图像字节，原始路径和带损伤描述的真值标签不进入模型提示词。首轮结构化语义输出包含目标种类（`target_type`）、疑似受损部位（`suspected_damaged_parts`）、可见损伤描述（`visible_damage_description`）、初评等级（`initial_damage_level`）、观察事实、引用图像编号、待核实疑点及结构化二次任务单（`secondary_task`：任务类型、瞄准部位、期望视角、指令与优先级）；次轮综合两轮图像与原问题输出确认目标种类、确认受损部位（`confirmed_damaged_parts`）、损伤分级（`damage_severity`）、综合损伤描述（`damage_description`）、`confirmed` / `ruled_out` / `still_uncertain` 判定、新增视觉证据与后续处置建议（`recommended_followup`）。
- `coordination/center.py`：`SurveyCenter` 负责在 `runs/coordination/<mission-id>/` 下拒绝覆盖已有非空目录、按中性文件名归档原图与 SHA-256、按目标隔离 VLM 调用失败并保留待处理状态、按 `dispatch_policy`（默认 `always_confirm`，无论首轮是否发现损伤均生成第二轮复查/完好复核任务；可选 `only_flagged` 仅派发首轮标疑目标）向第二批无人机生成交接包（目标编号、首轮原图、复查问题、重点区域与建议动作），以及导出 `report.json` 与 `report.md`。
- `coordination/run_replay.py`：读取配对回放清单（默认 `configs/missions/coordination_replay_3targets.json`），支持 `--stress-test` 模拟跨目标乱序到达、重复回传与延迟返航，用于无仿真条件下的调度与 VLM 闭环验证。
- `coordination/run_sim_e2e.py`：ProjectAirSim 两批 6 机（`Scout-1..3`、`Inspect-1..3`）端到端仿真桥接入口，配合 `configs/simulation/scene_airport_multi6.jsonc`（720p + 30 Hz + 保留 `Chase`）与 `configs/missions/coordination_sim_6uav.json`（三目标 75/90/105 m 分层巡航）。支持 `--probe-only` 实测 1/3/6 机实时帧率，也支持两批 3 机并行起飞实拍、5 Hz 位姿采样导出 `trajectories.json`（NED 与 ENU）、上传中心、调用 237 `qwen3.5:9b`（默认 `think=false`）两轮评估、返航降落及碰撞计数归档；配合 `coordination/video_recorder.py` 仅订阅在飞 3 机的 `Chase` + `FrontCamera` 流，实时合成 `1920×720` 纯中文四区视频（左上 3×2 实时画面、左下实时高度剖面、右上真实机场占用栅格二维轨迹态势图、右下 6 机色标遥测表），并在结束时自动调用 `ffmpeg` 转为浏览器可直播的 H.264 MP4。
- `coordination/visual_servo.py`：第二批复查机末端真实视觉伺服闭环模块（默认开启 `--visual-servo`，可 `--no-visual-servo` 切回纯航点基线）。采用 **1A 并行到点 + 串行独占 GPU 伺服** 调度：3 架复查机先并行巡航至各自伺服起点悬停，再依次获取异步互斥锁运行闭环控制，伺服全程不读取目标真值坐标。飞机与塔台（`dino_oblique`）共用单实例冻结 `DINOv2 ViT-S/14`（`SharedDinoMatcher`），直接以第一批交接包传回的斜俯视图提取目标原型，结合实时 RGB-D 深度采样与 `servo_closed_loop` 机体系速度控制律抵近并经连续 3 帧停机确认；机库（`opening_nadir`）复用 `opening_geometry.opening_candidates` 对正俯视深度图做屋面/室内双层分割，按破口像素偏移与屋面深度驱动机体系水平对准，核验正下方垂直通道净空后下降入室拍图并沿原位垂直退出。通过 `recorder.set_front_listener` 复用前视 RGB 流（避免双订阅冲突），并通过 `recorder.set_servo_overlay` 在前视画面实时叠加 DINO 热图 / 破口掩膜、目标准星、测距、速度指令及确认进度条，同时落盘逐帧轨迹至 `servo_logs/<target_id>_servo.json`。
- `visualization/multi_uav_traj_node.py` 与 `visualization/multi_uav_replay.launch.py`：ROS2 Humble 多机三维轨迹回放节点与启动入口，读取 `trajectories.json` 在 `world` ENU 坐标系发布 `/coordination/markers` 与 `/coordination/paths/*`，与 `map_view.py` 机场三维网格及占用栅格叠加显示在 `configs/rviz/multi_uav_coordination.rviz` 中。

## DOB-CBF-QP 安全视觉伺服滤波器

`src/control/cbf_qp_servo.py` 提供无侵入接入 `coordination/visual_servo.py` 的统一安全滤波层（通过 `--controller cbf_qp` 启用，默认保持 `baseline_p` 解耦比例伺服不变），将斜俯视目标抵近与正俯视破口穿顶入室统一到同一个严格凸对角二次规划（6 维变量：4 轴机体系速度 `[vf, vr, vd, yaw_rate]` + 2 个非负松弛变量）中求解：

- **相机交互矩阵视野屏障（FOV-CBF）**：根据实时目标归一化坐标 `(cx, cy)`、RGB-D 深度与相机俯仰角计算针孔图像雅可比 `normalized_fov_jacobian`，把目标不越出画幅安全框写成线性不等式约束，避免传统 IBVS 雅可比求逆奇异。
- **RGB-D 障碍屏障与短时盲区记忆（Depth-CBF + `LocalObstacleMemory`）**：斜视模式对深度图分块取第 5 百分位提取前景最近点（抑制边缘单像素飞点）；穿顶入室模式通过 `extract_opening_rim_obstacles_body` 提取屋顶破口内缘与钢檩条点云，并结合世界系 NED 短时体素记忆（默认 6 s TTL）在洞缘移出下视视野后继续维持水平圆柱安全漏斗约束。
- **速度扰动观测器（`VelocityDisturbanceObserver`）**：仅用相邻帧机载位姿差分速度与一阶惯性预测指令速度的残差在线辨识外部未知风扰动（不读风速真值），同步用于名义速度前馈抵消与鲁棒 CBF 约束右端项补偿。
- **毫秒级求解与消融开关**：将对角正定 QP 转为非负象限对偶 FISTA 求解（用精确最大特征值保证步长无发散，病态时回退 SciPy SLSQP），内置 `enable_fov_cbf`、`enable_depth_cbf`、`enable_obstacle_memory`、`enable_dob` 独立开关。
